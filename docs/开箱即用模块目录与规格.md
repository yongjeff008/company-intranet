# 开箱即用模块目录与规格

版本：V0.1 模块评审稿  
日期：2026-11-02  
关联文档：[需求规格说明书](需求规格说明书.md)

## 1. 设计依据与使用原则

本目录补充 CMS 的标准模块库，覆盖新闻、公告、视频、红头文件、首页跑马灯新闻、问卷调查，以及企业内网常用的其他模块。用户明确提出的六项列为核心模块；其他模块及优先级属于产品建议，等待范围评审，不等于已承诺全部首期交付。

参考常见 CMS 的三种做法：页面通过现成部件组合；内容可以按来源和条件聚合；相同内容可切换展示模板。下面的产品设计为结合本项目需求提出的方案，不代表被参考产品都具有相同行为，也不代表本项目依赖这些产品。

| 官方参考 | 已核实的能力 | 对本项目的启发 |
| --- | --- | --- |
| [SharePoint 页面部件](https://support.microsoft.com/en-us/sharepoint/web-parts-and-apps-in-sharepoint/using-web-parts-on-sharepoint-pages) | 新闻、文档、图片、活动、人员、快捷链接、倒计时和 Forms 等页面部件 | 建立可选择的标准模块库；展示和交互模块分别定义 |
| [SharePoint 内容聚合](https://support.microsoft.com/en-us/sharepoint/pages-in-sharepoint/use-the-highlighted-content-web-part) | 从站点等来源动态展示文档、新闻、视频等内容 | 模块绑定来源与筛选条件，避免为每个位置重复录入内容 |
| [WordPress Query Loop](https://wordpress.org/documentation/article/query-loop-block/) | 按内容类型、分类、作者等筛选，并配置列表、网格和重复项结构 | 数据来源与展示模板分开配置，允许不写代码组合展示 |
| [Drupal Webform](https://www.drupal.org/project/webform) | 通过扩展模块构建表单，支持复杂表单场景 | 问卷和报名共用表单基础能力，但各自明确业务规则 |
| [Liferay Asset Publisher](https://learn.liferay.com/web/guest/w/dxp/sites/displaying-content/using-the-asset-publisher-widget/displaying-assets-using-the-asset-publisher-widget) | 页面通过部件展示内容集合 | 聚合模块复用内容集合；集合筛选和视觉样式分别维护 |

资料核对时间：2026-11-02。以上为设计参考，具体产品版本和部署形态的能力可能不同。

### 1.1 模块、内容与模板的关系

- **内容类型**决定维护哪些字段及业务状态，例如新闻、红头文件、问卷。
- **模块类型**决定页面提供什么功能，例如新闻展示、文件下载、问卷填写。
- **展示模板**决定同一功能如何呈现，例如新闻可选择标题列表、图文卡片或焦点图。
- **模块实例**是页面上实际添加的一块区域，拥有独立的配置与数据来源。

一条新闻可以同时出现在新闻列表、首页跑马灯和专题中，均引用同一份内容。业务人员修改并发布后，各引用位置更新。轮播、跑马灯、网格不应各建一份重复新闻数据。

问卷、报名、反馈等交互模块具有服务器端提交、校验、权限和统计逻辑。修改其 HTML/CSS 只调整外观，不能新增题型、绕过参与限制或实现新的业务流程。新增功能需开发模块能力，再向模板开放受控接口。

### 1.2 双后台分工

| IT 配置后台 | 业务内容后台 |
| --- | --- |
| 选择模块、位置、模板、配色和显示数量 | 在授权范围维护新闻、文件、问卷等业务记录 |
| 设置来源部门、分类规则、可选数据范围 | 给记录设置分类、封面、有效期等业务属性 |
| 决定部门是否可用某模块、是否可手动推荐内容 | 按授权推荐、置顶或撤下本部门内容 |
| 配置阅读、参与、结果查看等权限边界 | 不能通过业务设置扩大 IT 已授权的数据范围 |
| 管理模板代码和布局发布版本 | 发布业务内容、查看授权范围的响应与统计 |

## 2. 模块统一规格

| 编号 | 所有适用模块需具备的能力 |
| --- | --- |
| BASE-01 | 模块库展示中文名称、用途、预览、支持的内容类型、配置入口和依赖能力；未满足依赖时说明原因。 |
| BASE-02 | 添加模块后可选择内置模板，再配置参数；有权限的 IT 人员可复制模板并编辑 HTML/CSS。 |
| BASE-03 | 每个模块实例可设置名称、标题显隐、尺寸、间距、背景和边框，具体参数以模板声明为准。 |
| BASE-04 | 内容模块支持自动筛选或人工选择；建议支持“人工推荐优先＋自动补足”，并按内容 ID 去重。 |
| BASE-05 | 人工选择内容时只列出当前有权选择的内容；IT 配置来源不代表可以获取原本无权读取的正文。 |
| BASE-06 | 内容必须满足已发布、当前有效、阅读权限等条件，人工置顶不能绕过这些条件。 |
| BASE-07 | 提供桌面和手机预览；标题过长、无封面、空数据和加载失败均有规定展示。 |
| BASE-08 | 模块配置使用草稿、预览、发布与回滚机制；内容仍按其自身生命周期独立发布。 |
| BASE-09 | 普通用户对隐藏、过期和受限模块不能通过数据接口取得不应获得的数据。 |
| BASE-10 | 没有内容时显示空状态或隐藏模块；管理预览可以使用明确标记的示例，线上不能自动生成业务内容。 |
| BASE-11 | 删除模块实例不删除内容、问卷答案或报名记录；删除业务对象另走其管理流程。 |
| BASE-12 | 自动播放的动画提供暂停方式，并尊重减少动态效果的系统偏好；视频默认不自动有声播放。 |
| BASE-13 | 内容计数、热门排行和聚合统计只能基于用户有权访问的范围，不通过数量泄露受限内容。 |
| BASE-14 | 新模块版本或模板升级前检查现有实例兼容性；不得静默清空配置和业务数据。 |

自动筛选默认按“置顶状态、发布时间倒序、稳定 ID”排序；人工选择默认采用人工顺序。是否允许业务人员调整推荐位，由 IT 为每个实例授权。普通内容更新后保留人工顺序；下线或失权后移出展示；自动补足只在启用该选项时执行。

## 4. 六类核心模块详细规格

### 4.1 M01 新闻资讯

| 项目 | 规格 |
| --- | --- |
| 用途 | 发布公司动态、部门新闻和专题报道；同一记录可在多个位置引用。 |
| 业务字段 | 标题、短标题（可选）、摘要、正文、封面、来源、作者、所属部门、分类、标签、发布时间和附件。 |
| IT 配置 | 来源部门、分类、标签、展示数量、排序、是否推荐优先、是否显示日期及摘要、封面比例和更多链接。 |
| 展示模板 | 标题列表、图文列表、卡片网格、首条大图＋后续标题；焦点图可交给 M07 引用。 |
| 业务操作 | 编辑、预览、发布、置顶（按授权）、下线；部门只能维护自己的新闻。 |
| 关键规则 | 修改标题和链接等信息后，各引用模块展示已发布版本；无封面时使用模板规定的无图布局。 |

验收：新闻发布一次后，能同时出现在本部门新闻列表、首页聚合和跑马灯中；再次发布修改后保持一致；下线后所有引用入口撤回。

### 4.2 M02 通知公告

| 项目 | 规格 |
| --- | --- |
| 用途 | 发布行政通知、维护公告、培训通知和重要提醒。 |
| 业务字段 | 标题、正文、所属部门、重要级别、发布及失效时间、附件、联系人；阅读范围不得超出授权范围。 |
| IT 配置 | 来源、普通/重要公告筛选、显示条数、日期格式、重要标识、过期显示策略。 |
| 展示模板 | 紧凑列表、重要通知卡片、顶部提示条；默认不使用强制弹窗。 |
| 关键规则 | 到期默认移出当前公告模块；历史公告是否可查由归档策略决定。历史可查和完全下线是不同操作，界面必须区分。 |
| 扩展边界 | 已读回执、强制确认、定向推送需另行启用，不能以“浏览过详情”自动认定员工已经确认。 |

验收：重要公告正确置顶；到期后按选定策略撤出当前列表或进入历史；无阅读权限者不能通过附件地址访问。

### 4.3 M03 视频与培训视频

| 项目 | 规格 |
| --- | --- |
| 用途 | 发布培训视频、会议录播和企业宣传视频。 |
| 业务字段 | 标题、介绍、封面、视频资源、来源、所属部门、分类、时长、讲师（可选）、字幕文件（可选）、相关资料。 |
| IT 配置 | 单视频或列表、筛选条件、卡片数量、封面比例、播放器支持选项、是否展示时长及讲师。 |
| 展示模板 | 视频网格、图文列表、单视频播放器；默认点击后播放，不自动有声播放。 |
| 关键规则 | 视频资源必须在可用后才能发布；链接无效时提示失效；视频权限与内容阅读权限一致。 |
| 扩展边界 | 上传、引用、转码、字幕和流媒体服务器按资源方案实现；课程、学习进度、考试和学分属于后续学习管理能力。 |

验收：同一视频可在培训页面与部门页面引用；有权用户可播放，受限用户无法直接获取视频资源；更换展示模板不重新上传视频。

### 4.4 M04 红头文件与正式发文

| 项目 | 规格 |
| --- | --- |
| 用途 | 集中发布正式文件，支持按文号、单位、年份、类别检索；红头外观由文件原件或详情模板表达。 |
| 业务字段 | 文件标题、文号、发文单位、发文日期、所属部门、文件类别、摘要、原件、附件、正文（可选）、生效与失效日期、关联文件、有效状态。 |
| IT 配置 | 文号与日期显隐、检索条件、列表列项、来源范围、是否允许下载、详情模板。 |
| 展示模板 | 文号列表、文件卡片、正式文件详情；原件建议用 PDF，其他格式可授权下载。 |
| 文件状态 | 业务有效状态为未生效、有效、失效或已废止；与草稿、已发布、已下线等发布状态分开。 |
| 版本规则 | 已发布原件不能静默替换；新版本或更正记录保留替换说明、操作记录及可追溯关系。原件的历史访问按独立授权控制。 |
| 权限规则 | 设置不允许下载时隐藏下载功能并限制专用下载接口，但浏览器可见内容仍可被保存，不能承诺“绝对不可复制”。 |
| 扩展边界 | 该模块负责正式文件发布与查阅；电子签章、套红生成、行文审批、密级审批和公文交换不自动包含。 |

文号是否按“发文单位＋年份＋序号”唯一、是否允许联合发文和无文号文件，需在原型评审时确认。系统不应在规则未确认前强行采用全站唯一文号。

验收：能按文号找到文件；有效状态清晰展示；新版本与原文件有明确关系；废止文件不进入“当前有效文件”列表，但可按授权查历史。

### 4.5 M05 首页跑马灯新闻

| 项目 | 规格 |
| --- | --- |
| 用途 | 在首页或部门页紧凑展示新闻头条和重要短消息，点击进入原内容。 |
| 内容来源 | 选择新闻/公告来源、人工选定内容或创建简短消息；短消息含文字、链接（可选）、有效期和所属部门。 |
| IT 配置 | 横向连续滚动、纵向逐条切换、静态显示；切换间隔或滚动速度、展示条数、标题长度、文字与背景颜色、图标和点击方式。 |
| 业务操作 | 维护原新闻和短消息；只有被授权时才能调整推荐顺序与展示有效期，不可修改全站布局。 |
| 关键规则 | 默认复用原内容短标题或标题；长标题可查看完整文本；无链接短消息不显示成可点击链接。 |
| 可用性 | 鼠标悬停和键盘聚焦可暂停；提供暂停操作；减少动态效果模式下使用静态或手动切换展示。 |
| 去重与失效 | 同一新闻在一个实例内仅出现一次；下线、过期、失权或删除后退出队列；无内容时按空状态规则处理。 |

这是本 CMS 内的头条展示模块，不依赖现有独立 marquee 项目，也不把其公网隧道或整屏特效默认引入企业内网。

验收：可不写代码切换滚动和静态模板；暂停后可读完整信息；点击新闻进入原详情；未发布消息不进入滚动队列。

### 4.6 M06 问卷调查

问卷作为原生交互模块设计，默认不依赖外部问卷 SaaS。若企业已有问卷平台，可在授权后提供外链入口，外链与原生问卷应明确标识，统计数据不能混用。

| 项目 | 规格 |
| --- | --- |
| 用途 | 员工满意度、培训反馈、需求征集及服务评价。 |
| 基础题型 | 单选、多选、单行文本、多行文本、数字、评分；说明文字不计为题目。 |
| 业务配置 | 问卷标题、说明、题目、顺序、选项、必填、长度或数值范围、开始/结束时间、参与范围、实名/匿名、每人提交规则、结果可见性。 |
| IT 配置 | 页面放置位置、卡片或嵌入模板、问卷来源范围、可授予业务管理员的题型与权限边界。 |
| 展示模板 | 问卷列表、单问卷卡片、嵌入填写；可显示未开始、进行中、已结束和本人是否已提交（适用时）。 |
| 生命周期 | 草稿→已发布待开始→进行中→已结束；业务人员可手动提前关闭。发布后未开始可按规则撤回，开始收集后的题目结构不可直接改写。 |
| 提交规则 | 服务端校验开放状态、参与资格、必填和范围；重复请求不得产生重复答卷；失败应保留可恢复的填写内容。 |
| 修改规则 | 已有答卷时不能删除题目、改变题型或重定义选项含义；需要变更则复制为新版本问卷，原答卷保留。 |
| 提交后修改 | 默认一次最终提交，提交前提示不能修改；是否开放截止前修改为后续配置项，不能默认为允许。 |
| 统计 | 单选统计人数和比例；多选明确分母并提示比例可超过 100%；评分统计分布及平均值；文本答案不公开展示。 |
| 管理结果 | 问卷所属部门中获结果权限的管理员查看、筛选、导出答卷；普通页面浏览权不等于结果权。 |
| 公开结果 | 默认不向普通用户显示；确需开放时，仅显示获授权的汇总，排除个人文本及可识别信息，小样本设置最小展示阈值。 |
| 导出 | 导出记录操作人、时间和问卷；匿名答卷不包含姓名、工号、账号或可反推身份的业务字段，并处理电子表格公式注入。 |
| 首期边界 | 不默认支持考试计分、复杂跳题、矩阵题、任意文件上传和自动审批；高级题型与条件逻辑作为增强项。 |

“匿名”需要在选择时说明技术含义，不能仅在页面隐藏姓名：

- **实名模式**：账号与答卷关联，按明确权限查看个人答案。
- **登录匿名模式（建议）**：登录用于校验资格和防重复；参与记录只记录资格标识与参与状态，答案不携带账号或可连接到该账号的答卷标识。业务管理员不可获取身份对应关系，日志与导出也不能无意建立关联。
- 不承诺基础系统管理员在任意环境下绝对无法推断身份；精确提交时间、小群体和自由文本也可能暴露身份，界面应如实说明。是否需要更强匿名保障，在评审后选择专门方案。
- 首期建议不开放免登录公开匿名问卷；若开放，应另定义防重复、限流和反滥用方案。

问卷关闭、参与资格变化和提交并发时，以服务端最终校验为准；关闭后禁止继续提交，并清楚提示当前状态。预览与测试答卷不得进入正式统计。

验收：可不写代码建立单选、多选和评分问卷；未开始不可提交，截止后停止；同一参与者的重复请求不重复计数；业务管理员不能查看其他部门答卷；有答卷后结构编辑受限；匿名导出无身份映射。

## 7. 模块包与内容维护入口

每个标准模块应作为完整可用能力交付，不只提供一张能摆到首页上的卡片。适用时包含：

1. 模块库中的预览与配置表单，至少一个可直接使用的模板和默认参数。
2. 对应的业务维护入口、列表、编辑表单、预览、发布和归档操作。
3. 前台列表、详情或交互页面；引用型模块复用原内容详情，不另建重复详情。
4. 阅读/参与/结果/维护权限、空状态、异常状态及手机适配。
5. 操作记录、业务版本、引用关系检查和必要的数据导出能力。
6. 清晰的依赖说明，例如视频存储、用户身份、表单引擎；缺依赖时禁止假装已可用。

后台菜单按业务对象归类。例如“新闻管理”维护新闻，M01/M05/M07 都可引用；“问卷管理”维护问卷和答卷。IT 增加模块实例不会为部门自动复制一套互不相关的新闻库。一个部门被授予模块维护权限后，后台才显示相应入口。

建议允许 IT 提供“企业门户首页”“部门首页”“培训专区”等配置组合预设，一次加入常见模块。预设只创建布局、配置与可选分类，不自动发布假新闻、假文件或假问卷。业务管理员进入后台时可得到引导与创建入口。

## 9. 新增验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| MOD-AC-01 | IT 新建一个新闻模块实例，选择列表模板并绑定部门 | 可无代码使用；该部门管理员在同一新闻管理入口维护内容 |
| MOD-AC-02 | 同一新闻被新闻列表、焦点图、跑马灯引用 | 只存一份新闻；修改后统一更新，下线后全部撤回 |
| MOD-AC-03 | 给有内容的实例更换模板或删除实例 | 业务内容及附件不丢失；其他引用实例继续工作 |
| MOD-AC-04 | 人工置顶一条已过期或用户无权阅读的内容 | 普通用户不能因置顶取得该内容或受限统计 |
| MOD-AC-05 | 创建带文号的文件并发布新版本，随后将旧版本废止 | 当前版本、变更说明及状态清晰；原件不能无记录被替换 |
| MOD-AC-06 | 首页跑马灯在手机及键盘操作下使用 | 可暂停、查看完整标题及打开原详情，不强制持续动画 |
| MOD-AC-07 | 创建、预览并发布问卷，生成测试与正式答卷 | 测试答卷与正式统计隔离，正式提交校验时间、资格与重复请求 |
| MOD-AC-08 | 修改已有答卷问卷的题型或选项含义 | 系统阻止直接破坏统计，允许复制新问卷保留旧数据 |
| MOD-AC-09 | 业务管理员查看、导出登录匿名问卷 | 无账号到答案的映射；非所属部门或无结果权限者不能访问 |
| MOD-AC-10 | IT 启用模板组合预设但业务尚未填充内容 | 展示空状态，不自动发布示例数据或开放空问卷收集 |
| MOD-AC-11 | 普通用户直接调用其他部门问卷统计、视频或文件接口 | 依据对应权限拒绝访问，不能仅依靠菜单隐藏 |
| MOD-AC-12 | 截止时间附近重复提交问卷，或并发活动报名 | 问卷不重复计数，截止校验一致；启用报名时不能超过名额 |

## 10. 模块范围待确认

1. 是否把全部“建议基础”模块纳入首期，还是先完成六类核心及其必要依赖？
2. 问卷需要哪些题型；是否需要跳题、多页、截止前改答和匿名保障？结果允许哪些角色查看？
3. 红头文件原件的主要格式是什么；是否需要在线预览、文号校验、正式文件更正与替代关系？
4. 公告过期后是可搜索的历史公告，还是完全下线？是否有必须签收确认的公告？
5. 跑马灯需要引用新闻即可，还是还需业务人员维护独立的短消息？
6. 是否已经有通讯录、视频平台、问卷平台和应用入口目录，可用于后续集成？
7. 哪些模块允许部门管理员维护人工推荐位？IT 是否需要锁定部分全站统一模块？

下一步应据选定模块绘制配置表单和业务录入表单，确认“IT 配一次、业务持续维护”的操作链路；随后再估算工作量与交付顺序。

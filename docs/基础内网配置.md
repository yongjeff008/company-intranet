# 基础内网配置

日期：2026-11-02。用户要求按 IT 管理员的工作方式，配置一个常见企业内网并提供普通用户公网入口。

## 已发布结构

站点名称：企业信息门户。首页使用舒展布局，部门页使用紧凑布局。初始配置采用绿色与浅色背景；2026-11-03 已扩展为十套可选主题，当前预览已应用「秋 · 拾光」。详见 [主题与配色](主题与配色.md)。部门名称和主题均可在后台修改。

| 页面 | 已配置模块 |
| --- | --- |
| 站点首页 | 今日要闻（整行跑马灯）、企业新闻（主栏，首条突出）、通知公告（侧栏）、公司文件（主栏）、员工调查（侧栏）、培训课堂（整行卡片） |
| 综合管理部 | 部门动态、行政通知、行政文件 |
| 人力资源部 | 人事通知、培训学习、人事文件、员工意见调查 |
| 财务管理部 | 财务通知、财务文件、财务动态 |
| 信息技术部 | 系统与服务公告、数字技能培训、技术动态、信息服务反馈 |

首页聚合全部部门的对应内容；部门页所有模块均绑定本部门来源。页面和站点设置已发布，普通用户可以访问。没有创建任何新闻、公告、文件、视频、短消息、问卷或答卷，后续由部门管理员填充。

## 角色与账号

| 账号 | 角色及范围 |
| --- | --- |
| admin | 保留原系统管理员账号 |
| it_config | IT 配置管理员，可配置站点与授权，不因此获得部门内容维护权限 |
| office_admin | 综合管理部内容管理员，可查看本部门问卷结果 |
| hr_admin | 人力资源部内容管理员，可查看本部门问卷结果 |
| finance_admin | 财务管理部内容管理员，无问卷结果查看权限 |
| it_editor | 信息技术部内容管理员，无问卷结果查看权限；与 IT 配置角色分开 |
| employee | 普通员工，只能浏览前台及参与已开放问卷，无部门授权 |

新账号均使用各自随机生成的密码。密码保存在本机 `.data/baseline-access.json`，普通用户访问说明另存 `.data/普通用户访问.txt`；均不进入 Git。原 admin 密码未修改。

## 普通用户公网入口

普通用户使用独立的临时 Cloudflare 域名，转发到本机 5088 服务。新域名避免继承先前预览域名的管理员 Cookie。访问仍需登录，以账号角色和服务端授权决定功能范围。

当前地址见本机 `.data/portal-public-url.txt`；隧道日志为 `.data/portal-tunnel.log`。域名是临时地址，重启隧道后可能变化，不能作为固定生产域名。

已验证公网 HTTPS 下可以登录 employee 并显示普通用户首页；该账号不显示 IT 或内容维护菜单，直接访问 IT 接口返回 403。四个部门页面均已发布，390px 手机页面没有横向溢出。

## 配置记录与再次应用

基础配置通过 `scripts/configure-baseline.py` 调用真实后台 API 完成，修改前的配置快照保存在 `.data/baseline-backup-*.json`，当前结构摘要在 `.data/baseline-config-report.json`。

重复运行会保留已有非空页面和同名账号，不重置其密码；不会插入业务示例内容。若 admin 密码已变更，可通过 `CMS_ADMIN_PASSWORD` 环境变量提供当前密码，而不是修改数据库或重置其他账号。

页面的后续调整优先通过 IT 后台进行，避免将基础配置脚本当作覆盖现有运营配置的工具。

## 1. 文档目的与需求依据

本文定义一个以企业内网为首个应用场景的可配置内容管理系统（CMS），作为产品设计、技术方案、任务拆分和验收的依据。2026-11-02 已确认后端 .NET / ASP.NET Core、数据库 MySQL、前端 React + TypeScript，并收到用户“开干”的明确指令，进入实现阶段。工程选择见 [技术选型与工程约定](技术选型与工程约定.md)，实际完成情况见 [开发进度](开发进度.md)。

用户已明确的要求：

1. 产品首先是 CMS，主要用于内容发布，当前将其用于企业内网。
2. 首页布局、模块样式、部门、各部门页面布局均可配置。
3. 日常配置通过模板选择和界面操作完成，无须编写 HTML、CSS。
4. 当现有模板无法满足要求时，允许具备技术能力的人员修改模板的 HTML、CSS。
5. 提供两类后台：IT 配置站点结构和展示方式；业务部门管理员维护本部门内容。
6. IT 配置部门、模块和管理员后，生成的站点内容为空，后续由业务人员填充。
7. 内容至少包括新闻、公告和培训视频，普通用户通过前台浏览。
8. 提供新闻、公告、视频、红头文件、首页跑马灯新闻、问卷调查等开箱即用模块，并形成可扩展的模块库。

模块详细需求见 [开箱即用模块目录与规格](开箱即用模块目录与规格.md)。其中六类核心模块为新增明确需求，其他模块和交付优先级为待评审建议。

本文中标注“建议”的规则用于形成可讨论的完整方案，不代表用户已经确认。未标注的补充行为作为本稿提出的需求，均可在评审时调整。

## 2. 产品目标与边界

### 2.1 产品目标

建设一套将站点展示、组织结构、权限和内容分开的 CMS。IT 可以在不改业务代码的情况下组合模板、页面、部门和模块；业务人员可以在不接触站点结构和代码的情况下持续维护内容；普通用户获得一致、清晰、可搜索的内网阅读体验。

产品应支持同一套内容使用不同模板展示；修改布局和样式不应要求重新录入内容。产品的内容、模板和模块机制应保持通用，部门空间作为企业内网场景中的内容归属与管理边界。

### 2.2 本期范围

| 范围 | 内容 |
| --- | --- |
| 前台 | 站点首页、部门首页、内容列表、内容详情、搜索、登录及无权限提示 |
| IT 配置后台 | 站点设置、模板、页面布局、模块、部门、管理员分配、发布配置、预览与回滚 |
| 业务内容后台 | 本部门内容、分类、素材、预览、发布、下线与历史版本 |
| 内容类型与交互 | 新闻、公告、培训视频、红头文件、跑马灯短消息与问卷；引用新闻的跑马灯复用新闻记录 |
| 标准模块库 | 六类核心模块，以及经评审选定的补充模块；详细清单与配置规则见模块规格 |
| 基础能力 | 用户与角色、权限校验、附件与视频资源、操作日志、备份恢复要求 |

### 2.3 暂不纳入本期基线

以下能力需要单独确认范围：在线审批与流程引擎、考试与学习进度、即时通讯、员工社区、超出基础问卷的复杂表单与数据报表、外部系统数据集成、多企业租户、多语言、任意第三方插件执行、面向普通业务人员的自由代码编辑。培训视频在本期按“视频内容发布”处理，不自动包含学习管理系统功能。活动报名、建议箱等列入模块候选库，评审选定后才纳入交付范围。

## 3. 角色与双后台

“双后台”表示两个职责清晰的工作空间，不要求使用两个独立系统、账户体系或服务。一个用户可以兼具多个角色；登录后只能访问其获授权的功能和数据范围。

| 角色 | 主要职责 | 权限边界 |
| --- | --- | --- |
| 平台超级管理员 | 初始化系统、管理 IT 管理员、恢复误配置 | 全局权限，应限制账号数量 |
| IT 配置管理员 | 配置站点、模板、部门、模块和权限；发布展示配置 | 可调整结构与展示；不因该角色自动承担日常内容维护 |
| 部门内容管理员 | 创建、修改、发布、下线本部门内容，维护本部门素材和分类 | 默认不能改模板代码、页面布局、部门结构或其他部门内容 |
| 普通用户 | 浏览其有权访问的已发布内容 | 不能进入管理功能；不能读取草稿和未发布配置 |

建议首期不进一步拆分编辑、审核、发布角色；部门内容管理员直接发布。若需要多人审核，则增加独立角色和发布审批流程，见待确认项。

### 3.1 IT 配置后台工作范围

- 管理站点标识、导航、页眉页脚和全局视觉参数。
- 新建、排序、停用部门，配置部门页面并分配部门管理员。
- 选择模板，添加与排列模块，配置模块样式和内容来源。
- 管理模板版本，在授权代码编辑入口修改 HTML、CSS。
- 使用预览检查页面，在确认后发布配置；必要时恢复上一配置版本。
- 查看配置变更、权限变更和模板代码变更记录。

### 3.2 部门内容后台工作范围

- 只显示用户有权管理的部门；管理多个部门时可切换当前部门。
- 创建新闻、公告、培训视频、红头文件及获授权的短消息，维护分类、封面及附件。
- 创建和发布获授权的问卷，管理题目、开放时间与参与规则；查看及导出结果需另有结果权限。
- 保存草稿、查看实际展示预览、发布和下线内容。
- 查看本部门内容状态、修改时间、修改人和发布记录。
- 管理部门素材库，处理失效视频及附件引用。

## 4. 业务流程

### 4.1 从空系统建立可用内网

1. 平台超级管理员完成初始化并授予 IT 配置权限。
2. IT 管理员设置站点名称、标识与导航，选择站点首页模板。
3. IT 管理员创建部门，为各部门选择页面模板并配置模块和样式。
4. IT 管理员为模块指定内容类型、来源部门、分类、排序等规则，并分配部门管理员。
5. IT 管理员预览并发布配置，系统生成具有完整结构但没有业务内容的站点。
6. 部门管理员登录内容后台，创建并发布新闻、公告或培训视频。
7. 普通用户访问前台，查看按模块规则展示的已发布内容。

### 4.2 修改页面外观

IT 管理员从当前线上配置创建修改草稿，调整模板、模块和样式，预览并发布。未发布的修改不影响线上页面；切换模板或调整模块不删除原有内容。

### 4.3 扩展模板

IT 管理员选择现有模板并复制为自定义模板，修改 HTML、CSS，在内容绑定接口允许的范围内完成扩展。系统校验后生成新版本，使用预览数据或授权真实内容检查效果，再由 IT 管理员应用到目标页面并发布。

## 5. 核心概念与关系

| 概念 | 定义 | 关键关系 |
| --- | --- | --- |
| 站点 | 一个独立配置的内容门户，本期以单站点为基线 | 包含全站首页、导航和多个部门空间 |
| 部门空间 | 某部门拥有的页面、内容、素材和管理权限范围 | 部门可拥有多个管理员；用户可管理多个部门 |
| 页面 | 具有访问路径和布局配置的展示单元 | 使用页面模板，包含若干模块实例 |
| 页面模板 | 定义页面整体区域、结构和可配置项 | 可以被多个页面复用 |
| 模块模板 | 定义某类模块的展示结构、样式和内容占位接口 | 可以被多个模块实例复用 |
| 模块实例 | 页面上实际添加的一块内容区域 | 保存样式参数及数据来源，不保存业务内容正文 |
| 内容 | 新闻、公告、视频等独立业务记录 | 归属一个部门，可被多个授权模块引用 |
| 素材 | 图片、附件、视频文件或视频链接 | 具有归属、引用关系和访问权限 |
| 配置版本 | 某次可预览、发布或恢复的展示配置快照 | 与内容版本分别管理 |

建议本期以“站点首页—部门首页—内容列表—内容详情”为固定页面体系，每种页面具有可配置模板。任意新增页面、嵌套页面和可视化菜单树的深度另行确认。

## 6. 功能需求

### 6.1 站点与导航

| 编号 | 需求 |
| --- | --- |
| SITE-01 | IT 管理员可配置站点名称、Logo、页眉页脚、主导航和基础主题参数。 |
| SITE-02 | 导航支持链接到站点页面、部门页面和授权访问的其他地址，并可排序、隐藏和启用。 |
| SITE-03 | 全站默认主题应允许配置主色、字体预设、页面宽度、间距等有限且有说明的参数。 |
| SITE-04 | 首页可聚合多个部门内容；具体来源、展示数量和顺序由模块配置确定。 |
| SITE-05 | 未创建内容时显示清晰的空状态；模板示例内容不得自动发布为业务内容。 |

### 6.2 部门与管理员配置

| 编号 | 需求 |
| --- | --- |
| DEPT-01 | IT 管理员可创建、修改、排序、启用和停用部门，设置名称、标识、介绍和访问路径。 |
| DEPT-02 | 每个部门可分别选择布局模板、配置模块和样式，不要求所有部门拥有相同页面结构。 |
| DEPT-03 | 部门可从统一模板生成初始布局，再独立修改；部门名称不应写死在模板代码中。 |
| DEPT-04 | IT 管理员可为一个部门分配多个管理员，也可将一个管理员分配给多个部门。 |
| DEPT-05 | 管理员移除或权限收回后，应不能继续通过页面或接口访问原管理范围。 |
| DEPT-06 | 停用部门应同时处理前台导航、访问入口和关联模块；默认保留部门内容与历史数据。 |
| DEPT-07 | 有关联内容的部门不得直接无提示删除；应提供停用或先迁移归属的处理路径。 |

建议本期部门采用平级结构；如果需要公司、中心、部门等多级组织，应补充继承、聚合与权限规则。

### 6.3 可视化页面配置

| 编号 | 需求 |
| --- | --- |
| PAGE-01 | IT 管理员可为站点首页和各部门页面选择页面模板。 |
| PAGE-02 | 提供界面操作添加、删除、移动、排序和隐藏模块；拖拽可以作为交互形式，但不能成为唯一操作方式。 |
| PAGE-03 | 支持配置模块所在区域、宽度或列占比、间距和显示数量；超出模板支持范围时应明确提示。 |
| PAGE-04 | 模块标题、标题显示方式、背景、边框、图片比例、文字摘要等可通过表单或预设配置。 |
| PAGE-05 | 允许按模板提供的范围调整样式；日常操作不要求用户输入 HTML、CSS。 |
| PAGE-06 | 支持预览站点首页、部门页面、列表页和详情页，并检查至少桌面与手机宽度的效果。 |
| PAGE-07 | 布局和样式修改先保存为草稿，发布后才对普通用户生效。 |
| PAGE-08 | 发布前检查无效模板、缺失模块、失效数据来源及不兼容配置；阻止会使页面无法渲染的配置发布。 |
| PAGE-09 | 配置发布应形成完整版本；普通用户不应看到只发布了一半的页面配置。 |
| PAGE-10 | 支持恢复上一可用配置版本；恢复布局不恢复或覆盖业务内容。 |

### 6.4 模板体系与代码编辑

建议区分页面模板、模块模板、内容列表模板和内容详情模板。模板应声明用途、适用内容类型、可配置参数及兼容版本。

| 编号 | 需求 |
| --- | --- |
| TPL-01 | 提供模板列表和预览，让 IT 管理员先选模板再配置参数。 |
| TPL-02 | 首期至少提供两种不同页面布局方案，以及新闻列表、公告列表、视频卡片等模块展示方案；具体设计在原型阶段确定。 |
| TPL-03 | 内置模板可复制为自定义模板；建议内置原件保留，方便恢复与升级。 |
| TPL-04 | 授权 IT 管理员可编辑模板 HTML、CSS；普通部门管理员不能进入代码编辑入口。 |
| TPL-05 | 提供受支持的内容字段、列表循环和参数绑定说明，以及编辑时可查阅的示例。模板作者不应依赖直接访问数据库。 |
| TPL-06 | 自定义模板必须正确绑定标题、正文、封面、视频等受支持字段；字段缺失时提供可理解的回退展示。 |
| TPL-07 | CSS 应限制在目标页面或模块作用范围，避免自定义模块影响其他模块和后台。具体机制由技术方案确定。 |
| TPL-08 | 模板保存与模板发布分开；发布前校验语法、必要绑定和禁止代码，并允许预览与回退。 |
| TPL-09 | 模板版本应明确记录被哪些页面使用。修改共享模板后，列出受影响页面，未经发布不得自动改变线上展示。 |
| TPL-10 | 页面绑定明确的模板版本；升级版本时保留兼容参数，对不兼容项提示映射、重置或取消，不能静默丢失配置。 |
| TPL-11 | 删除模板前检查引用关系；已被线上页面引用的版本不得直接删除。 |

建议首期自定义能力限于 HTML、CSS 和系统提供的数据绑定表达式，不开放任意 JavaScript、服务端代码或任意数据查询。富文本、模板代码和内容变量均应经过符合用途的安全处理，不能因管理员编辑模板而获得服务器执行能力。

### 6.5 模块与内容来源

| 编号 | 需求 |
| --- | --- |
| MOD-01 | 标准模块库支持新闻、公告、视频、红头文件、首页跑马灯新闻、问卷调查六类核心模块；图文介绍、快捷链接等补充模块按评审范围交付，详见模块规格。 |
| MOD-02 | 同一模块类型可添加多个实例，每个实例具有独立的标题、模板、样式和数据来源。 |
| MOD-03 | 内容模块可按内容类型、来源部门、分类和标签筛选，设置数量及排序方式。 |
| MOD-04 | 支持最新发布、置顶优先等明确的排序规则；多个内容排序值相同时仍保持稳定顺序。 |
| MOD-05 | 首页可按配置聚合多个部门内容；部门页默认展示本部门内容，是否允许跨部门引用由 IT 控制。 |
| MOD-06 | 内容来源筛选不能绕过阅读权限；即使内容被聚合到首页，无权限用户也不能获取其正文或附件。 |
| MOD-07 | 删除或隐藏模块只改变页面展示，不删除其引用的内容与素材。 |
| MOD-08 | 无匹配内容时可以显示空状态或隐藏模块，该行为由 IT 配置。 |
| MOD-09 | 模块中的“更多”链接进入与其筛选条件一致的列表页；点击内容进入对应详情页。 |
| MOD-10 | 内容类型、模块功能、展示模板和模块实例分别管理。同一新闻可在列表、焦点图和跑马灯中引用，不重复录入正文。 |
| MOD-11 | 问卷等交互模块须包含完整维护、提交校验、权限及结果管理；HTML/CSS 模板只调整展示，不改变业务规则。 |
| MOD-12 | 模块交付应覆盖配置后台、业务维护入口、前台展示与必要的权限及异常处理；不能只交付页面上的展示卡片。 |

### 6.6 内容维护

建议内容采用通用字段与类型专属字段组合。首期支持以下预定义内容及问卷，不自动包含由业务人员定义任意数据模型的功能。问卷题目可通过表单编辑，但不能据此创建任意服务器端业务流程。

| 内容类型 | 主要字段 |
| --- | --- |
| 通用字段 | 标题、摘要、所属部门、分类、标签、封面、作者或来源、正文、附件、状态、发布时间、创建与修改记录 |
| 新闻 | 通用字段；支持图文正文与相关附件 |
| 公告 | 通用字段；可设置置顶和有效期，过期处理见生命周期规则 |
| 培训视频 | 标题、介绍、封面、视频资源、附件；时长在可可靠获取时自动提取，否则允许填写 |
| 红头文件 | 标题、文号、发文单位、发文日期、原件、附件、有效状态与替代关系；正式版本须可追溯 |
| 跑马灯短消息 | 短文本、可选链接、所属部门和有效期；如果引用新闻则直接使用原新闻，不建立重复记录 |
| 问卷 | 标题、说明、题目与选项、开放时间、参与范围、实名/匿名设置、结果权限；答卷独立保存 |

上述常规内容适用下表生命周期；问卷另按模块规格中的草稿、待开始、进行中、已结束状态及题目版本规则管理。红头文件的生效、失效、废止状态与发布状态分开。

| 编号 | 需求 |
| --- | --- |
| CNT-01 | 部门管理员可创建、编辑和复制本部门内容，界面根据内容类型显示对应字段。 |
| CNT-02 | 提供富文本编辑器，支持标题、段落、列表、图片、链接等常见内容；不要求业务人员写 HTML。 |
| CNT-03 | 对必填项、字段长度、链接及资源可用性提供明确校验，失败时保留已填写内容。 |
| CNT-04 | 内容可保存为草稿；建议支持自动保存并显示最近保存时间。 |
| CNT-05 | 内容预览应使用目标页面的实际展示模板；未发布内容的预览不可被普通用户访问。 |
| CNT-06 | 首期按草稿、已发布、已下线三个主要状态管理；已发布内容编辑时保留线上版本，重新发布后替换。 |
| CNT-07 | 发布后按模块筛选规则自动出现在对应页面，无须部门管理员再手工添加到页面布局。 |
| CNT-08 | 支持内容下线；下线后从前台列表、搜索和详情访问中撤回，保留后台历史。 |
| CNT-09 | 保存重要修改与发布版本；可查看修改人、时间，并恢复为编辑草稿，经发布后上线。 |
| CNT-10 | 支持按标题、类型、状态、分类和时间查询本部门内容。 |
| CNT-11 | 管理员并发编辑同一内容时提示版本冲突，不得直接静默覆盖他人已保存修改。 |
| CNT-12 | 内容删除应有确认与恢复机制；仍被引用的素材不能随内容无提示永久删除。 |
| CNT-13 | 模块库中各业务对象的专属字段、有效期、版本和权限规则按模块规格执行；通用内容操作不能绕过这些约束。 |

建议内容阅读范围默认“全部已登录内网用户”，内容维护范围仍严格限制在授权部门。若需要仅部门成员可读，则需要可靠的用户部门身份及额外权限规则。是否支持定时发布、公告到期自动下线和批量操作，列入待确认项。

### 6.7 图片、附件与培训视频

| 编号 | 需求 |
| --- | --- |
| ASSET-01 | 素材区分部门归属与共享范围，部门管理员不能任意删除其他部门素材。 |
| ASSET-02 | 上传文件应校验类型、大小和权限；限制由 IT 配置或平台策略规定，并在上传前提示。 |
| ASSET-03 | 培训视频至少支持一种经确认的视频来源方案：上传文件，或引用已有内网视频地址；两者是否同时提供见待确认项。 |
| ASSET-04 | 显示上传进度和失败原因；对大视频的断点续传、转码及分片播放需求依据容量评估确定。 |
| ASSET-05 | 视频无法播放、附件不存在时给出明确提示，避免详情页整体失败。 |
| ASSET-06 | 发布内容前检查必需的视频或附件资源是否可用，不能将未完成上传的资源作为可播放内容发布。 |
| ASSET-07 | 素材删除前显示使用情况；已发布内容使用中的素材禁止直接删除或要求完成替换。 |
| ASSET-08 | 附件和视频的实际访问接口应执行阅读权限校验；不能只依靠隐藏页面链接保护文件。 |

### 6.8 普通用户前台

| 编号 | 需求 |
| --- | --- |
| VIEW-01 | 用户可访问站点首页、部门首页、列表与详情，导航和布局使用已发布配置。 |
| VIEW-02 | 前台只展示有权阅读的已发布内容，不返回草稿字段、后台配置或管理员信息等无关数据。 |
| VIEW-03 | 内容详情展示标题、发布部门、时间和正文；按内容类型显示附件或视频播放器。 |
| VIEW-04 | 提供已发布内容搜索，支持至少按关键词查询标题和摘要，并按部门、内容类型筛选；正文全文检索作为待确认增强项。 |
| VIEW-05 | 内容下线或权限变化后，搜索结果与直接链接均遵循新的可见性，缓存不得继续暴露已撤回内容。 |
| VIEW-06 | 不存在、已下线、无权限等情况提供合适页面，不能泄露受限内容标题或摘要。 |
| VIEW-07 | 页面应适配常见桌面和手机宽度，视频、表格和长标题不应破坏主要布局。 |

## 7. 权限要求

| 操作 | 超级管理员 | IT 配置管理员 | 部门内容管理员 | 普通用户 |
| --- | --- | --- | --- | --- |
| 管理 IT 管理员 | 是 | 否 | 否 | 否 |
| 站点、部门、导航配置 | 是 | 是 | 否 | 否 |
| 模板代码与展示配置发布 | 是 | 是，按授权 | 否 | 否 |
| 分配部门管理员 | 是 | 是 | 否 | 否 |
| 创建、发布部门内容 | 是 | 需另有内容权限 | 仅授权部门 | 否 |
| 管理部门分类和素材 | 是 | 需另有内容权限 | 仅授权部门 | 否 |
| 阅读前台内容 | 按阅读权限 | 按阅读权限 | 按阅读权限 | 按阅读权限 |
| 查看日志 | 全局 | 配置及授权范围 | 本部门内容记录 | 否 |

所有权限必须在服务端接口执行。前端隐藏菜单只用于交互引导。直接修改部门 ID、内容 ID、素材 ID 或预览链接不能获取未授权数据。内容发布权限与阅读权限分开管理；发布权限不能自动扩大阅读范围。

问卷维护、参与、结果查看和答卷导出为独立权限。部门内容管理员不因具有内容发布权限而自动获得所有问卷答案；匿名模式还须满足模块规格中的数据与导出限制。

## 8. 数据与版本约束

1. 部门、内容、模板和模块使用稳定标识；重命名不能导致数据丢失或内容关联断开。
2. 内容归属、发布状态、模板绑定和配置发布必须具有明确的一致性边界，失败时不得留下不可恢复的半完成状态。
3. 模板代码、页面配置、内容分别保留版本；恢复其中一类不能静默覆盖其他两类。
4. 模板升级、模块删除和部门停用应检查引用影响；默认优先保留业务内容。
5. 内容从一个部门迁移到另一个部门时，必须明确新归属、管理权限、阅读权限及原链接处理方式；首期是否提供迁移入口待确认。
6. 提供必要的配置、内容和素材备份要求；恢复时能够重建其引用关系。
7. 所有日期时间保存与展示应采用统一时区策略；默认展示北京时间，具体实现由技术方案确定。

## 9. 非功能需求

### 9.1 安全与访问

- 建议企业内网要求登录后访问，身份来源可接本地账号或企业统一身份，最终方式待确认。
- 会话、密码和文件访问采用合理的安全处理；配置项和日志不得暴露密钥、密码或完整会话凭据。
- 富文本、上传素材、链接和自定义模板应控制脚本注入、危险文件及越权访问风险。
- 管理功能执行敏感操作时记录操作人、时间、目标和结果；应覆盖权限分配、配置发布、模板修改、内容发布与删除。
- 自定义模板失效时应有可恢复路径，不能导致管理后台无法登录和恢复。

### 9.2 性能与容量

用户规模、并发量、内容量、视频大小和网络带宽尚未提供，以下为建议验收目标，须在确定测试环境和负载后定稿：

| 项目 | 建议目标或约束 |
| --- | --- |
| 常见非视频页面 | 在约定内网环境、目标负载和缓存条件下，P95 可交互时间不超过 3 秒 |
| 内容发布可见性 | 正常情况下发布后 10 秒内可在对应前台页面查询到 |
| 后台配置保存 | 对约定规模配置，P95 响应时间不超过 2 秒，不包含文件上传 |
| 视频播放 | 按确认的带宽与视频规格单独制定首帧、并发及拖动播放指标 |
| 搜索 | 按最终内容量和检索方案制定响应指标，不套用未知容量下的固定承诺 |

### 9.3 可用性与可维护性

- 模板配置界面提供预览、参数说明、默认值和必要的重置入口。
- 部门内容后台以内容维护为主，不向业务人员暴露部署、数据库等技术配置。
- 网络或保存失败时提供可重试操作，尽可能保留未提交内容。
- 页面主要导航、表单和常用操作应可用键盘完成，文字与背景具有可读对比度。
- 保留运行日志、备份和恢复说明；正式上线前确定备份频率、保留周期和恢复目标。

## 10. 首期交付建议

本期建议交付一个闭环：IT 可配置空站点，部门可维护六类核心模块所需业务记录，用户可通过前台浏览或参与问卷，展示和内容修改均有权限边界与恢复能力。模块库中其他候选能力不因列入清单而自动成为首期承诺。

| 阶段 | 交付范围 | 评审重点 |
| --- | --- | --- |
| 需求与原型 | 确定待确认项，绘制双后台与前台核心流程，设计模板配置原型 | 是否满足“不写代码也能配置”的使用要求 |
| CMS 基础 | 用户角色、部门、固定内容类型、素材、文件版本与内容发布闭环 | 数据归属、角色权限与内容状态 |
| 配置与模板 | 页面模板、模块、样式表单、数据绑定、预览与版本发布 | 内容和展示分离，空站点可成立 |
| 自定义模板 | HTML/CSS 编辑、校验、作用范围控制及版本兼容 | 修改模板可恢复且不会破坏内容 |
| 交互模块 | 基础问卷维护、参与校验、匿名规则、结果权限和导出 | 答卷完整性、截止校验与结果隔离 |
| 上线准备 | 搜索、响应式适配、日志、备份恢复、部署与验收 | 真实负载、权限和恢复可用性 |

顺序仅用于后续计划讨论，不能理解为已确定工期或已完成设计。

## 11. 核心验收场景

| 编号 | 操作与条件 | 预期结果 |
| --- | --- | --- |
| AC-01 | IT 新建人事部、财务部，分别选择不同布局并分配管理员，发布配置 | 两部门前台结构可不同；页面无虚构新闻和视频；管理员权限正确 |
| AC-02 | IT 通过界面给首页增加新闻列表、公告和视频模块，修改样式与顺序 | 全程无须写代码；草稿阶段线上不变；发布后展示符合配置 |
| AC-03 | IT 修改某模块样式，保持其他配置不变 | 修改仅影响目标实例或明确选择的作用范围，不意外影响其他模块 |
| AC-04 | 人事部管理员尝试从界面或直接接口修改财务部内容、模板和布局 | 操作被拒绝；财务部草稿和素材信息不被泄露 |
| AC-05 | 部门管理员保存新闻草稿，再发布 | 草稿普通用户不可见；发布后自动进入匹配模块和列表 |
| AC-06 | 修改已发布新闻但仅保存草稿 | 普通用户继续看到已发布版本；再次发布后切换为新版本 |
| AC-07 | 将已有内容的部门页切换为其他兼容模板 | 内容和附件不丢失，模板参数按兼容规则处理 |
| AC-08 | 复制模板并修改 HTML/CSS，预览后应用与发布 | 支持的字段正确展示；非法代码被阻止；修改不破坏后台 |
| AC-09 | 模板升级缺少原模块所需参数或使用中的模板被删除 | 系统提示影响并阻止无提示破坏，提供保留或恢复路径 |
| AC-10 | 下线公告或停用部门，再访问列表、搜索、旧详情链接和附件链接 | 各入口按发布与权限规则一致处理；后台数据保留 |
| AC-11 | 普通用户打开新闻、公告和有效培训视频 | 类型对应信息完整；视频可播放，附件按授权下载 |
| AC-12 | 页面配置错误，IT 恢复上一配置版本 | 前台恢复可用布局；期间新发布的业务内容不被覆盖 |
| AC-13 | 两个管理员同时修改同一内容 | 后保存者收到版本冲突提示，可处理差异，不静默覆盖 |
| AC-14 | 删除被已发布内容使用的素材 | 系统展示引用并阻止直接破坏线上内容 |
| AC-15 | 对备份进行恢复演练 | 配置、内容和素材引用能恢复，结果满足确认后的恢复目标 |

新增模块验收详见 [模块规格第 9 节](开箱即用模块目录与规格.md#9-新增验收场景)，覆盖文件版本、跑马灯复用、问卷提交与匿名导出等行为。

## 12. 待确认事项

以下事项不会阻碍讨论原型，但应在相应功能设计和开发前明确。建议值仅用于评审。

| 编号 | 待确认问题 | 当前建议或备选 |
| --- | --- | --- |
| Q-01 | 用户如何登录，是否已有 AD、LDAP、企业微信、钉钉等身份系统？ | 优先复用已有企业身份；没有则首期使用本地账号 |
| Q-02 | 前台是否全部要求登录，是否存在不登录可访问的页面？ | 默认全部登录后访问 |
| Q-03 | 部门是平级还是多级组织，是否有集团与子公司？ | 首期平级，避免未定义的继承规则 |
| Q-04 | 内容是否全部员工可读，是否需要按部门、角色限制阅读？ | 首期全部登录用户可读；管理权限按部门隔离 |
| Q-05 | 部门管理员能否直接发布，是否需要审核人？ | 首期直接发布；有审核要求则另定义流程 |
| Q-06 | 部门布局只允许 IT 配置，还是可授权部门管理员调整？ | 首期仅 IT 配置 |
| Q-07 | 视频上传到本系统还是引用已有平台？单文件大小及并发观看人数多少？ | 根据现有资源和容量选择，先保证一种方案完整可用 |
| Q-08 | 六类核心模块之外，还需哪些标准模块？是否需要业务人员自定义字段与类型？ | 根据模块目录选择补充范围；自定义内容模型作为独立能力评估 |
| Q-09 | 是否需要定时发布、到期下线、置顶有效期和内容审核？ | 公告建议支持有效期；具体调度与审批另定 |
| Q-10 | 首页、列表、详情是否都要自由配置？是否允许任意新增页面？ | 首期固定页面体系，模板和模块可配置 |
| Q-11 | HTML/CSS 自定义是否足够，是否确有执行自定义 JavaScript 的业务需求？ | 首期不开放任意脚本 |
| Q-12 | 员工人数、峰值并发、新闻存量、附件与视频容量？ | 确认后制定性能与存储指标 |
| Q-13 | 部署在何处，是否只能内网访问，是否需要远程访问？ | 部署与网络方案单独制定，不能默认公网开放 |
| Q-14 | 搜索是否需要正文、附件全文、视频字幕检索？ | 首期标题与摘要检索，其他检索单独评估 |
| Q-15 | 是否需要阅读统计、已读回执、通知推送、视频学习记录？ | 不包含在普通发布功能中，按需明确 |
| Q-16 | 站点是否需要多个独立门户？公司品牌和首批模板偏好是什么？ | 首期一个站点；根据品牌资料设计模板 |
| Q-17 | 内容历史、删除恢复、操作日志和备份分别保留多久？ | 上线前确认保留周期及恢复目标 |
| Q-18 | 是否需要导入既有内容、批量发布、部门内容迁移和配置导出？ | 明确真实迁移对象后确定首期范围 |
| Q-19 | 问卷需要哪些题型、匿名保障、结果查看范围和改答规则？ | 基础题型与登录匿名按模块规格讨论，高级跳题等单独评估 |
| Q-20 | 红头文件的文号规则、原件格式、更正及替代流程是什么？ | 按模块规格确认，电子签章与行文审批另行立项 |
